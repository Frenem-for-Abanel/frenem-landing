A one-time code is a password with a short life, and it deserves the same
respect at rest. Frenem products sign people in with emailed codes, and the
database never holds one in a readable form: what is stored is a keyed hash,
computed the moment the code is generated and useless on its own.

The mechanics matter because short codes are small. A six-digit code has only
a million possible values, so a plain hash could be enumerated in seconds by
anyone holding a copy of the table. We therefore compute an HMAC with a key
that lives outside the database, which means a database copy alone verifies
nothing. Verification recomputes the HMAC, compares in constant time, and
retires the code on first use, on expiry, or after a fixed number of failed
attempts, whichever comes first.

The underlying rule is broader than sign-in: the database should never hold
anything that can be replayed as-is. Rows get copied, backups travel, and
query logs outlive their context. Storing only what can verify, never what can
authenticate, is the cheapest security decision we make, because it is made
once, at the schema.
